# ZMK Studio Custom v1.0.1

ZMK Studio Custom is an unofficial personal/community fork of ZMK Studio focused on practical split-keyboard workflows. It preserves standard Studio behavior while adding runtime combo editing, editable custom behaviors, clearer key legends, backup/restore, mouse settings, and standalone desktop builds.

This is an incremental update to v1.0.0. The main feature set is unchanged, while Mouse Settings visibility and release/deployment behavior have been refined.

## What changed in v1.0.1

### Mouse Settings now follows firmware capability

Mouse Settings visibility is driven directly by the connected firmware's pointing capability.

- If the firmware is built with `CONFIG_ZMK_POINTING=y`, the pointing-settings RPC is available and Mouse Settings is shown.
- If pointing support is not compiled in, the pointing-settings RPC is unavailable and Mouse Settings stays hidden.
- Studio does not scan the keymap for mouse bindings.

This keeps the frontend lightweight and avoids special-case scanning for aliases, nested behaviors, custom behaviors, or mouse bindings placed on different layers.

### Web and desktop builds aligned

The web application and standalone desktop builds are now produced from `main`, so the downloadable applications and deployed web frontend stay aligned.

## Web application

https://custom-zmk-studio.onrender.com/

For USB access in the browser, use a Chromium-based browser with Web Serial support such as Chrome or Edge.

## Enhanced runtime combo management

The custom Studio UI supports:

- viewing existing runtime combos
- creating, editing and deleting combos
- naming and reordering combos
- grouping and organizing combos by layer
- editing layer masks
- selecting physical key positions visually
- previewing combo positions
- editing timeout and advanced combo properties
- using supported custom behaviors as combo outputs
- persisting supported runtime combo changes through matching custom firmware

The compatible firmware provides a runtime combo pool. The current default pool size is 64 combos, subject to available firmware resources and configuration.

## Custom behavior support

The application can display and edit compatible custom behaviors exposed through firmware metadata and the custom Studio RPC extensions.

Examples used by supported keyboard configurations include:

- Layout Shift
- Layout Shift On / Off
- layout-shift-aware key presses and mod-taps
- OLED Toggle
- BASE View Cycle
- Display Timeout
- Half Sleep Timeout
- Bluetooth profile helpers
- runtime-editable hold-tap behaviors
- runtime-editable sticky-key behaviors
- other metadata-aware custom behaviors supplied by firmware

Runtime behavior editing is schema-driven, so the UI reads the configuration fields exposed by firmware instead of hard-coding every individual behavior.

## Improved keymap visualization

The keymap view includes clearer labels and icons for supported behaviors, including:

- Bluetooth profile select, clear, clear-all, next, previous and disconnect
- OLED toggle
- BASE View Cycle
- display and sleep timeout controls
- Layout Shift / OS switching
- Windows and macOS indicators where exposed by the keymap
- bootloader, reset and output-selection behaviors
- mouse movement and scrolling
- left, middle and right mouse buttons
- mouse buttons 4 and 5
- layer-aware labels
- improved mod-tap and layer-tap presentation

Board-specific labels depend on the metadata and behavior definitions supplied by that keyboard's firmware.

## Backup and restore

Backup/restore support covers editable Studio state supported by the connected firmware, including:

- layers
- layer names
- key bindings
- runtime combos
- combo names and ordering
- combo layer masks
- supported custom behavior configuration

Restore reconciles live layer and behavior IDs rather than assuming IDs remain identical between sessions.

## Standalone desktop applications

Desktop builds are available for:

- Windows x64 — setup EXE and MSI
- macOS — universal DMG for Apple Silicon and Intel
- Linux AMD64 — AppImage and DEB
- Linux ARM64 — AppImage and DEB

Windows installers are currently unsigned. macOS uses the repository's current ad-hoc signing configuration, so normal operating-system warnings for unsigned/community builds may appear.

## Firmware compatibility

Normal ZMK Studio functionality can work with ordinary Studio-enabled ZMK firmware.

The enhanced features in ZMK Studio Custom — especially runtime combo editing, runtime custom-behavior editing, custom metadata/protocol extensions, and pointing settings — require matching firmware-side support.

Installing this application by itself does **not** add those capabilities to stock ZMK firmware.

## Firmware setup for the enhanced v1.0.1 feature set

Users who want the complete feature set should point their ZMK configuration at the tested custom ZMK fork/commit below.

### 1. Point `config/west.yml` at the compatible ZMK fork

```yaml
manifest:
  remotes:
    - name: sukumar
      url-base: https://github.com/Sukumar002

  projects:
    - name: zmk
      remote: sukumar
      revision: b19edf953498bf9d0a4598eb39d04e7e43339b08
      import: app/west.yml

  self:
    path: config
```

That pinned ZMK commit already imports the matching custom `zmk-studio-messages` definitions through its own `app/west.yml`. Do **not** add a second Studio messages repository to the keyboard config.

### 2. Enable Studio on the central half or dongle

For a conventional split, Studio belongs on the central half. For a dongle-based split, the dongle is normally the central Studio target.

A typical `build.yaml` entry is:

```yaml
- board: <your-central-board>
  shield: <your-central-shield>
  snippet: studio-rpc-usb-uart
  cmake-args: -DCONFIG_ZMK_STUDIO=y
```

Replace the placeholders with the board and shield used by your keyboard.

### 3. Runtime combo editing

When Studio RPC is enabled, the custom firmware enables runtime combo editing automatically:

```text
CONFIG_ZMK_COMBO_RUNTIME_EDITING=y
```

It may also be set explicitly in the central board/shield configuration if desired.

### 4. Runtime custom-behavior editing

The custom firmware likewise enables runtime behavior editing automatically when Studio RPC is active:

```text
CONFIG_ZMK_BEHAVIOR_RUNTIME_EDITING=y
```

The firmware supplies pre-allocated runtime-editable behavior pools. The current implementation includes editable hold-tap and sticky-key behavior instances.

### 5. Enable mouse / pointing functionality when required

If the keyboard uses ZMK mouse keys or other pointing functionality and you want Mouse Settings, add:

```conf
CONFIG_ZMK_POINTING=y
```

The pointing-settings Studio RPC is compiled only when pointing support is enabled.

ZMK Studio Custom v1.0.1 uses that capability directly:

- pointing RPC available → Mouse Settings visible
- pointing RPC unavailable → Mouse Settings hidden

No keymap scanning is required.

### 6. Build and flash the new firmware

After changing `west.yml` and the relevant build/config files:

1. Commit the changes to the keyboard configuration repository.
2. Let the normal ZMK GitHub Actions build complete.
3. Flash the newly generated firmware to the central half or dongle.
4. Flash peripheral halves as required by that keyboard's normal build process.
5. Connect the Studio-capable central device to ZMK Studio Custom.
6. Unlock Studio when prompted.

The enhanced Combo and Behaviors sections become functional only when the connected firmware exposes the corresponding custom RPC/protocol support.

## What the matching custom firmware adds

The compatible ZMK fork provides:

- runtime combo pool
- combo editing and persistence
- combo naming and ordering
- combo layer masks
- Studio combo RPC subsystem
- runtime custom-behavior pools and persistence
- Studio custom-behavior RPC extensions
- behavior metadata used by the frontend
- matching custom Studio protocol messages
- pointing/mouse settings RPC when `CONFIG_ZMK_POINTING=y`
- larger Studio RPC buffers required by combo/custom-behavior requests

Board-specific functions such as OLED controls, timeout controls, layout-shift behaviors and Bluetooth helper behaviors remain keyboard/keymap features. They are not automatically added merely by using this Studio application or firmware fork.

## Compatibility matrix

| Application | Stock Studio-enabled ZMK firmware | Matching custom firmware |
| --- | --- | --- |
| Official ZMK Studio | Standard Studio features | Standard features; custom extensions may not have UI support |
| ZMK Studio Custom v1.0.1 | Standard supported functionality | Full enhanced feature set described above |

For the complete custom feature set, use **ZMK Studio Custom v1.0.1 + the pinned compatible custom ZMK firmware**.

## Why this fork exists

This fork is intended to experiment with and improve workflows particularly useful on programmable split keyboards. It is **not intended to replace official ZMK Studio**.

Where practical, normal upstream Studio behavior is preserved while the custom application and matching firmware add functionality that currently exists outside the upstream protocol/UI.

## Disclaimer

ZMK Studio Custom is an unofficial community/personal fork.

Compatibility is not guaranteed with every keyboard, ZMK revision, custom firmware implementation, custom behavior, operating system, browser, or future Studio protocol revision.

Back up important keymaps/settings before experimenting with runtime editing or custom firmware.

## Code signing and updater signing

Platform code signing and Tauri updater signing are separate mechanisms.

The current Windows installers are unsigned. The macOS application uses the repository's current ad-hoc signing setup. Users may see operating-system warnings when installing community builds.

Updater signatures, when present on a tagged release, verify that an update originated from this project; they do not make an installer trusted by Windows or macOS code-signing systems.
