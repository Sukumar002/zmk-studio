# ZMK Studio Custom v1.0.2

v1.0.2 is an incremental bug-fix and usability release on top of v1.0.1. It does not change the custom firmware protocol and remains compatible with the same matching custom ZMK firmware line used by v1.0.1.

## What's fixed

### Desktop backup export now behaves like a desktop application

The desktop app no longer relies on a browser-style hidden `<a download>` action for backup export.

On Windows, macOS, and Linux the app now:

1. opens a native **Save As** dialog,
2. lets you choose the destination and filename,
3. writes the JSON backup to that exact path,
4. shows an in-app **Backup exported** notification with the saved path, and
5. provides a **Show in folder** action to reveal the exported backup in Explorer/Finder/the system file manager.

Export failures are surfaced to the user instead of only appearing in developer logs.

The web app keeps the browser-native download flow, where the browser itself owns the download notification and destination.

### Runtime layer capacity is now visible

The Layers sidebar now explains why **Add layer** is available or disabled:

- when firmware exposes spare runtime layer slots, Studio shows the number remaining;
- when no slots are exposed, Studio says that no spare layer slots are available from firmware.

The actual add/remove/reorder/rename layer RPC behavior was already present in v1.0.1. Firmware still controls how many runtime-addable layers exist.

For Hana, the matching firmware now reserves four spare Studio layer slots.

## Compatibility

No new RPC or protocol version is introduced in v1.0.2.

Existing v1.0.1-compatible custom firmware continues to work. To use runtime layer creation, the keyboard firmware must expose reserved layer capacity; otherwise the Add layer control remains disabled.

## Downloads

Use the assets attached to this release for Windows, macOS, and Linux, or use the hosted custom ZMK Studio web app.
