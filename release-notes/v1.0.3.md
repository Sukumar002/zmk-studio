# ZMK Studio Custom v1.0.3

v1.0.3 is a focused usability release that makes day-to-day keymap editing easier to read and faster to manage, especially for combos, layers, and runtime-tunable behaviors.

## What's new

### Compact combo view is much more informative

Compact combo rows can now alternate with a gentle cross-fade between the keys that trigger a combo and the action the combo performs.

Examples include:

- `J + K` → `Backspace / Alt`
- `A + F` → the configured mouse-layer action
- Layer-Tap actions clearly distinguish their target layer with a compact layer chip.

Trigger labels now resolve the tap side of Mod-Tap and Layer-Tap keys instead of showing generic behavior names such as “Mod-Tap”.

The compact hover preview remains available for quickly locating the combo's physical key positions.

### Layer controls now live with the layer

Rename and Delete controls have moved into each layer row in the Layers sidebar.

They stay visually quiet until the row is hovered or keyboard-focused, while their space remains reserved so layer names do not shift. Delete confirmation and undo behavior are unchanged.

### Settings is now capability-driven

Settings only shows controls that the connected firmware actually supports.

When no interactive settings are available, Studio shows a simple empty state:

> **Nothing to tune here yet**  
> Your keyboard firmware doesn’t currently support changing these settings in real time.

Mouse settings remain hidden on firmware without pointing support.

### Live behavior tuning for compatible custom firmware

Compatible custom firmware can expose runtime-editable behavior settings directly to Studio.

For the current Hana firmware line this includes factory Mod-Tap, Layer-Tap, and Bluetooth Profile hold-taps. Numeric timing fields use a slider plus an exact editable value, while other supported fields use the appropriate select/toggle controls.

Changes take effect immediately in the live behavior configuration and can be persisted using Studio's normal Save flow.

## Compatibility

Standard Studio-enabled ZMK firmware continues to provide the standard Studio feature set.

The live behavior-tuning controls require firmware built with the matching custom runtime-behavior support. If the connected firmware does not expose those capabilities, Studio simply hides the unavailable controls and shows the empty Settings state when nothing else can be configured.

## Reliability

The web build path has been streamlined for normal development, while full desktop builds are reserved for explicit validation and releases. Release-data fetching is also authenticated to avoid GitHub API rate-limit failures during deployment.
